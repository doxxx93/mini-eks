# mini-eks

Build a managed Kubernetes service that gives users what EKS gives them: by hand first, then as controllers in both Go and Rust. Public GitHub repo `doxxx93/mini-eks`.

- `STEPS.md` is the single linear checklist. When the user asks what's next, name only the first unchecked step instead of offering a menu.
- Each step ends with a Korean note `notes/NN-*.md` following `notes/TEMPLATE.md`. Notes are the user's learning record: draft or review as they ask, and always fact-check the "실제 EKS·GKE에서는" section against docs or source, with links.
- Go and Rust implement the same CRDs and must pass the same language-neutral checks. Go goes first; Rust follows.
- Layout: one `main` branch, split by directory. `manual/NN-slug/` holds each phase 1 step's manifests and commands (only that step's delta; the cluster state carries over from earlier steps). `api/` is the shared CRD YAML, `test/` the language-neutral checks, `go/` and `rust/` the two evolving implementations. When a step is done, tag `step-NN` on main. Branches are only short-lived per-step workspaces (e.g. an Orca worktree) merged back into main.
- Tools: `mise.toml` pins kubectl 1.37, kind 0.33.0 (kind's default node image is v1.37.0) and shellcheck 0.11.0. The task runner is mise tasks, not just or moon: `doctor`, `check [NN]` and `lint` exist; more (e2e, cluster up/down, builds) come at step 10, and CI calls `mise run` via `jdx/mise-action`. Phase 1 commands are typed by hand, not wrapped in tasks. OrbStack's bundled kubectl 1.33 at `/usr/local/bin/kubectl` is outside the one-minor skew, so run commands from inside this directory where mise wins on PATH. etcdctl ships inside the etcd image; no extra host tools are needed for phase 1.
- Checks: every step with a 확인 item adds `test/steps/NN-slug.sh` (sourcing `test/lib.sh`) so a first-time learner can verify their own result. Checks only inspect state and point at where to look; they never perform the step. The management cluster is kind `mgmt` (`MGMT_CLUSTER` overrides). The first tenant is `tenant-a` (`TENANT` overrides) with service CIDR `10.32.0.0/16` (its `kubernetes` Service IP is `10.32.0.1`), kept apart from the management cluster's `10.96.0.0/16`. Its PKI follows kubeadm's file layout under the gitignored `pki/tenant-a/`; the x509 extensions and SANs live in `manual/02-pki/openssl.cnf`, and commands must work with both macOS LibreSSL and OpenSSL 3+. When a step generates files that stay out of git (keys, kubeconfigs), its `manual/NN-slug/README.md` shows the resulting tree instead of placeholder files, so the ignore rules stay strict. Scripts must run on macOS bash 3.2: write `${var}` when Korean text follows a variable, which `mise run lint` enforces. Step 10 reuses these checks against controller-made tenants.
- Environment: OrbStack Docker + kind for phases 1–4. Lima (vz, nestedVirtualization; needs Apple M3 or later) + KubeVirt only from phase 5.
